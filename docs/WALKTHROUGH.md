# EcoSnow 인터랙티브 안내

## 분석과 시나리오

기존 React/Vinext/Next.js 관리자 앱은 8개 메뉴, 기관별 로컬 레코드, IndexedDB 사진, 4개 입력 화면과 5개 작업 상태를 사용한다. 입력·저장은 기존 이벤트와 도메인 함수를 그대로 호출한다. 사진 AI·실제 결제·외부 제보는 미연결이므로 작동하는 것처럼 안내하지 않는다.

- 전체 안내(37단계): 관리 구역 등록 → 현장 기록 시작 → 실제 관찰값·수동 사진 대체 사유 → 기준 선택·산정 또는 보류 → 실제 사용 기록 → 작업 완료 → 후속 확인 → 기록 완료 → 이력 조회 → 비교자료가 없는 리포트 이해 → 체험 플랜 선택.
- 메뉴별: 관리 구역 등록, 현장 업무 전체, 이력 조회·수정, 절약 리포트, 기관 성장·보상, 체험 요금제, 제품·배치 등록.
- 최초 방문은 안내 수락/나중에 하기 창을 제공한다. 상단 `사용법 안내`, `이 기능 사용법 배우기`로 다시 실행할 수 있다.

## 구현과 상호작용

추가 라이브러리 없이 React portal과 현재 앱 콜백으로 구현했다. 현재 단계형 화면·모바일 드로어 준비와 별도 연습 저장소 전환을 세밀하게 연결하기에 적합하며 기존 의존성과 잠금 파일을 변경하지 않는다.

`walkthrough-model.ts`는 시나리오·연습 자료와 완료 조건을, `walkthrough.tsx`는 오버레이·위치 계산·키보드·코치 마크를 담당한다. UI에는 `data-guide` 식별자를 추가했다.

네 개의 어두운 화면 조각으로 타깃 부분을 비워 실제 클릭을 허용한다. 강조 테두리는 pointer-events를 가로채지 않는다. 클릭 단계는 해당 버튼을 눌러 앱 상태/저장 결과가 충족돼야 진행한다. 선택·체크는 실제 change 이벤트와 값을 확인한다. 입력 단계의 `입력 확인`은 비어 있거나 유효하지 않은 값을 통과시키지 않는다. 설명만 확인하는 단계는 명시적인 `확인했습니다` 버튼으로 구분한다. 일반적인 무조건 ‘다음’ 버튼은 없다.

이전/건너뛰기/종료/Escape를 제공한다. 이전 단계는 저장한 작업을 취소하지 않고 해당 화면을 다시 보여준다. 건너뛰기로 필요한 입력을 생략하면 이후 실제 저장·상태 전환 검사가 계속 막을 수 있다. 이때 이전 단계로 돌아가 입력하거나 안내를 종료할 수 있다.

타깃은 DOM 변경·스크롤·리사이즈·visualViewport를 관찰해 다시 측정한다. 메뉴 타깃은 모바일 드로어를 열어 준비한다. 기다리던 요소가 없어도 앱을 임의 조작하거나 자동 저장하지 않고 대기·이전·건너뛰기·종료를 제공한다. 툴팁은 좌우 공간을 우선 사용하고 부족하면 위아래로 배치한다. 입력 단계는 라벨 전체 대신 실제 input/select/textarea 좌표를 측정한다. 높이가 부족하면 설명 영역만 스크롤하고 이전·건너뛰기·종료·입력 확인 버튼은 고정해 잘리지 않게 한다. reduced-motion 설정을 존중한다. 포커스는 강조된 실제 컨트롤과 안내 버튼 사이로 제한하고 초기/완료 대화상자를 구분한다.

## 데이터 보호

- 실제 키 `ecosnow-admin-v1`과 기존 사진 DB를 유지한다.
- 연습은 `ecosnow-walkthrough-practice-v1`에 별도로 저장한다. 연습 기관 ID와 작업의 데모 플래그로 실제 실적과 구분한다. 서버 전송/결제/실제 제보를 호출하지 않는다.
- 시작할 때 실제 기관·화면·작업·수정 대상·기준 선택과 저장 전 폼 값을 보관한다. 종료/완료 시 실제 저장 데이터를 다시 읽고 원래 화면과 입력을 복원한다. 실제 사진 업로드 중이면 완료까지 시작을 보류한다.
- 연습 중 다른 탭이 실제 자료를 바꾼 경우 저장 충돌 경고를 유지해 오래된 폼으로 덮어쓰지 않도록 한다. 손상된 실제 자료를 자동 초기화하지 않는다.
- `ecosnow-onboarding-v1`은 완료/미루기 여부와 시각만 저장한다. 완료 메시지 시점에 완료를 기록하며 재방문 자동 안내를 반복하지 않는다. 저장 권한/용량 문제로 실패하면 알려준다.
- 새로고침 시 진행 중이던 안내 자동 재개는 제공하지 않는다. 원래 실제 저장소로 돌아오며 상단에서 다시 시작할 수 있다. 연습 기록은 분리된 키에 남지만 다음 안내 시작 시 새 연습 자료로 교체한다.

## 검증

기존 타입·린트·빌드·도메인 테스트를 유지하고 안내 시나리오·안전 저장소·실제 상태 완료 조건 단위 검사를 추가했다.

```sh
npm run typecheck
npm run lint
npm test
npx --no-install next build
```

실제 Chromium 반복 검사 (playwright-core 별도 준비):

```sh
PLAYWRIGHT_MODULE=/tmp/ecosnow-browser/node_modules/playwright-core/index.mjs ADMIN_TEST_URL=http://127.0.0.1:5174/ node scripts/verify-walkthrough-browser.mjs
PLAYWRIGHT_MODULE=/tmp/ecosnow-browser/node_modules/playwright-core/index.mjs ADMIN_TEST_URL=http://127.0.0.1:5174/ node scripts/verify-walkthrough-menus.mjs
```

전체 37단계를 1440/768/390/360px에서 실제 입력·저장·완료한다. 빈 입력 진행 차단, 스포트라이트 좌표, 말풍선/타깃 비겹침, 연습 전후 실제 JSON 일치, 종료/재실행/이전/건너뛰기, 첫 방문 상태 저장을 확인한다. 메뉴별 7개 안내와 리사이즈 시 드로어 준비, 저장 전 원래 폼·수정 대상 복원도 검사한다. 기존 관리자 업무/요금제 검사는 첫 방문 모달을 미룬 조건에서 그대로 실행한다. 스크린샷은 Git에서 제외한 `outputs/walkthrough/`에 저장한다. 실제 휴대폰 키보드·스크린리더 기기 검수는 별도 과제다.

## 강조 위치·잘림 회귀 검사

1363×688 제보 크기, 1536×600, 768×500, 390×640, 360×480 및 125% visual viewport 확대에서 실제 입력칸과 테두리 정합, 안내창·버튼 전체 노출, 타깃과 비겹침, 스크롤·리사이즈, 입력 수정 후 오류 제거를 검사한다. `walkthrough-layout.ts`의 배치 계산은 단위 테스트로도 확인한다.

```sh
PLAYWRIGHT_MODULE=/tmp/ecosnow-browser/node_modules/playwright-core/index.mjs ADMIN_TEST_URL=http://127.0.0.1:5176/ node scripts/verify-walkthrough-layout.mjs
```

이미지는 `outputs/walkthrough-layout/`에 저장한다. 브라우저/시스템 확대와 visual viewport는 CSS 픽셀 좌표로 처리하며, 고정 버튼의 실제 영역을 측정해 테스트한다.
