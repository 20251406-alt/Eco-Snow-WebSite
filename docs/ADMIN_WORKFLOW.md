# EcoSnow 관리자 로컬 워크플로

## 현재 범위

기존 React/Vinext 앱의 네비게이션·패널·브랜드 CSS·빌드 설정을 유지했다. CCTV 주소와 임의 위험도 점수에 의존하는 화면은 제거했다. 기존 `ecosnow-cameras` 브라우저 값은 삭제하지 않는다. 기존 정량 계산 유틸리티와 그 테스트는 보존했지만 새 화면은 `app/admin/domain.ts`의 조건 기반 산정을 사용한다.

7개 메뉴: 홈, 관리 구역, 현장 확인·정량 살포, 작업 이력, 절약 리포트, 기관 성장·보상, 기관 설정.

1. 기관 설정에서 기관·관리자, 제품·제조 배치를 등록한다.
2. 관리 구역에서 위치·면적(㎡)·경계·용도·현장 특성을 등록한다. 카메라는 필요 없다.
3. 현장 기록을 시작한다. 구역·제품은 당시 값으로 복사한다. 새 구역/새 작업은 빈 관찰값에서 시작한다.
4. 사진 또는 수동 사유, 관찰 시각, 실제 면적·깊이·노면 온도·사전 제설 상태를 기록한다. 현장 측정/관리자 입력/데모 출처를 구분한다.
5. 제품 적용 기준을 선택하여 산정한다. 기준 없으면 확인 필요, 측정 누락이면 추가 정보, 적용 범위 밖이면 보류한다. 명시적 관리자 기준도 출처·확인자·적용 범위가 필요하다. 면적×g/㎡÷1000만 사용하고 눈 깊이 임의 계수는 없다. 각 수치와 계산 결과는 최대 1조 단위까지 지원한다.
6. 담당자가 현장 확인으로 진행한다. P1은 산정 보류여도 실제 사용 기록을 남길 수 있다. 실제 제품·배치·kg·면적·시각·선택 비용을 등록한다. 0 kg은 사유가 필요하다.
7. 작성 중 → 현장 확인 → 작업 완료 → 후속 확인 대기 → 기록 완료로 진행한다. 실제 작업과 후속 정보가 없으면 완료할 수 없다. 사진이 어려우면 사유와 수동 관찰로 대체한다. 잔설·효과 부족도 기록할 수 있다. 완료 후 추가 살포는 후속 확인을 다시 요구한다.
8. 시즌·전년도 비교 기간·전년도 실제 사용 원장·출처·확인 상태를 등록한다. 구매량이나 재고량은 소비량으로 집계하지 않는다. 실제 추가 살포 포함, 데모 제외, 기록 ID 중복 집계 방지. 작업 정정/삭제 시 집계도 변경된다.
9. 전년도 0/미입력은 절감률 없음. 증가 시 양수 증감량과 음수 절감률을 표시한다. 비용이 누락되면 임의 비용 계산을 하지 않는다. 월별 합계와 구역별 합계 및 실제 작업 명세를 표시한다. 전년도 자료는 기간별 수동 합계이며 월별 자료가 없을 때 추이를 생성하지 않는다.
10. 시즌 종료 전, 비교 범위 불일치, 자료·후속 확인·필요 제설 수행 미확인, 정책 미설정이면 등급은 보류한다. 정책 경계/할인율은 기본값이 없다. 담당자 평가 확인과 현재 근거가 일치할 때만 4단계 자체 배지를 표시한다. 자체 실천 배지는 공인 환경인증이 아니다.

## 저장·인증의 한계

- 메타데이터는 `ecosnow-admin-v1` localStorage, 사진 원본은 기관/사진 ID별 IndexedDB에 저장한다. 화면과 입력 모델에서 기관별 자료를 구분하지만 **인증·서버 접근제어가 아니다**. 같은 브라우저에 접근한 사람이 다른 로컬 기관을 선택할 수 있다.
- 서버 DB·계정·공유 저장·동기화·권한·감사 로그 변조 방지·사진 백업은 구현되지 않았다. 공용 운영 전 별도 구현이 필요하다. 배포 링크가 같아도 다른 기기끼리 로컬 기록을 공유하지 않는다.
- 파일 선택과 실제 촬영 시각은 다를 수 있으므로 시각은 담당자가 확인한다. 이미지는 8MB 이하. 자동 EXIF 분석이나 흰색 픽셀 면적 추정은 하지 않는다.
- 자동 저장은 작업 입력에 적용한다. 구역/설정/실제 사용/후속 양식은 저장 버튼을 눌러야 한다. 저장 실패를 알리며 성공으로 표시하지 않는다. 손상된 데이터는 자동 초기화하지 않는다. 다른 탭이 변경했으면 덮어쓰기를 막고 새로고침을 요구한다.
- JSON 내보내기는 전체 로컬 기관 메타데이터이며 사진은 포함하지 않는다. 가져오기 UI는 제공하지 않는다. 삭제한 사진 파일은 IndexedDB에 남을 수 있어 로컬 사진 정리는 후속 과제다. 브라우저 데이터 삭제 시 기록이 소실될 수 있다.
- 사진 AI는 `PhotoAnalyzer` 인터페이스와 unavailable 어댑터만 구현했다. 실제 모델·자동 면적/깊이·학습·정확도는 없다. 수동 경로가 실제로 작동한다.
- 제보는 `ReportAdapter` 인터페이스와 명시적 데모 입력만 있다. 티맵 제휴/API·실시간 수신·운전자 보상은 없다. 데모 제보에서 시작한 작업도 데모로 고정되어 실적에 섞이지 않는다.
- 검증된 제품 기준·보상 정책·원자료는 운영자가 제공해야 한다. 샘플 수치나 가짜 실적을 초기 데이터로 넣지 않는다.

## 실행·검증

Node.js >=22.13.0, Linux. 기존 체크아웃을 사용한다.

```sh
npm run install:ci # 의존성 없거나 잠금 파일 변경 시
npm run dev -- --host 0.0.0.0 --port 5173
npm run typecheck
npm run lint
npm test
```

`npm test`는 빌드·Worker 산출물·서버 HTML과 도메인 테스트를 실행한다. 화면 변경 시 별도 브라우저 검사도 권장한다. Playwright는 프로젝트 의존성에 추가하지 않았다. Chromium과 별도 설치한 playwright-core가 있는 경우:

```sh
PLAYWRIGHT_MODULE=/tmp/ecosnow-browser/node_modules/playwright-core/index.mjs node scripts/verify-admin-browser.mjs
```

`CHROMIUM_PATH`, `ADMIN_TEST_URL`로 검증 실행 환경을 지정할 수 있다. 브라우저 검사는 별도 컨텍스트에서만 시연 기록을 생성하므로 실제 사용 브라우저 데이터를 변경하지 않는다. 사진·산정/보류·실제 사용·상태 전환·새로고침·기관 구분·모바일·저장 실패를 확인한다.

배포는 사용자 요청 시에만 진행한다. 연결된 GitHub main에 푸시하면 Vercel 자동 배포가 실행될 수 있다. 코드 배포와 로컬 현장 기록의 공유는 다르며, 기록·사진의 기기 간 공유에는 별도 서버가 필요하다.

## 데모 체험

사이트의 `데모 데이터로 둘러보기` 버튼 또는 `/?demo=1` 링크는 별도 `[데모]` 기관에 구역 2개, 가상 제품·기준, 완료/작성 중 작업, 가상 제보를 한 번만 추가한다. 기존 기관·기록이나 이미 수정한 데모 자료는 덮어쓰지 않는다. 데모 기록은 실제 사용량·절감 성과·배지 평가에서 제외된다. 20 g/㎡, 2.4 kg, 3 kg 등은 산술·상태 전환 시험용 값이며 검증된 적용량이 아니다. 기관 선택에서 기존 기관으로 돌아갈 수 있다.

데모 v2는 기존 데모 기관의 빈 관찰·후속 항목, 사용 전·후 예시 도식, 전년도 가상 원장, 미확정 정책 입력값을 1회 보충한다. 전년도 가상 원장도 `demo`로 표시되어 실제 비교에서 제외된다. 정책의 비율은 시험용이며 확정·할인 지급을 하지 않는다. 실제 기관 자료는 변경하지 않는다. 이후 사용자 편집을 반복해서 덮어쓰지 않는다.
